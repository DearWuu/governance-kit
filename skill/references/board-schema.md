# 进度板 schema

解析权威是引擎 `rules.parse_board()`，本文件是它的人类可读契约；两者不一致时以代码为准并改文档。

## 进度板位置

- 进度板 = 仓库根的 `进度板.md`（索引）+ `进度/`（每任务一文件）。
- 位置由 `core.board_paths()` 统一决定：cfg 里 `board.path` / `board.tasks_dir` **任一非空即视为显式配置**，两键原样生效（未写的那键为空即不启用），显式配置最优先。
- 两键都空时自动发现：根目录 `进度板.md` 或 `进度/` 存在即用根位置；其次 `docs/进度板.md` 或 `docs/进度`（兼容旧位置）；都没有则本仓无进度板，解析返回空、不报 BOARD 告警。

## 形态一：每任务一文件（推荐）

- 目录由 `board.tasks_dir` 指定（默认自动发现为根目录 `进度/`），只扫该目录**第一层** `.md`，子目录里的文件不参与。
- 扫描不排除任何文件名：说明文件、模板文件同样会被建条目。它们必须写合法 frontmatter 并把 `status` 设为 `挂起`（`title` 标注「非任务」），否则状态为空即报 `BOARD-SCHEMA`。`govern init` 生成的 `进度/README.md` 就是这种写法。
- 每个文件一个任务，文件名 kebab 命名，内容 = frontmatter + 正文。
- 模板 `example-task.md` 本身会被当成一条真实任务解析；不需要时删掉或改名放进子目录。

### frontmatter 字段

| 字段 | 必填 | 引擎校验 | 说明 |
| --- | --- | --- | --- |
| `title` | 是 | 否 | 缺失回退到正文首个标题，再回退到文件名 |
| `status` | 是 | 是 | 必须是 `board.statuses` 之一，否则 `BOARD-SCHEMA` |
| `owner` | 是 | 是 | `dev-<个人>` 对应的开发者或 agent 标识 |
| `updated` | 是 | 是 | `YYYY-MM-DD`；解析失败报 `BOARD-SCHEMA` |
| `goal` | 是 | 是 | 一句话目标，用来判断是否 UI 类条目 |
| `evidence` | 是（可空串） | 完成时非空 | `已完成` 且为空 → `BOARD-SCHEMA` |
| `doc` | 是（可空串） | 否 | 指向人读文档，没有就留空串 |

必填指 key 必须出现；非完成态 `evidence`/`doc` 留空串即可。

- 解析很朴素：`---` 必须在第 1 行，逐行 `key: value`，值两侧引号可选；不支持列表、嵌套、多行值。
- 引擎只读上述已知 key，其余 key 会被忽略（不报错），因此额外字段可用于人工流程。

### 正文约定

`## 目标` / `## 进展` / `## 下一步` / `## 证据` / `## 完成方` 五段，按需省略空段。

## 形态二：旧式单文件（兼容）

- `board.path`（默认自动发现为根目录 `进度板.md`）内的条目写成 `## [状态] 标题`。
- 条目下方第一条 `负责: xxx` 被当作 owner，第一条 `YYYY-MM-DD` 被当作 updated。
- `legacy_status` 把旧词映射到当前枚举：`待办`→`待启动`、`部分完成`→`进行中`、`完成`→`已完成`。既不在 `statuses` 也不在 `legacy_status` 的原文 → `BOARD-SCHEMA` 非法状态。
- 旧式条目不校验必填字段，也不校验 `已完成` 的 evidence，因此**不能承载双完成入口**，只适合迁移期或历史归档。
- 同一任务不要两种形态各登记一次：会被算成两条。

## 状态枚举

`待启动` / `进行中` / `待验收` / `已完成` / `挂起`

```
待启动 ──> 进行中 ──> 待验收 ──> 已完成
              │           │
              └──> 挂起 <─┘
                    └──> 进行中（恢复）
```

- `待验收` = 等人工复核，不是等下一个 agent 动手；把「等别的 agent」写成待验收属于状态误用。
- 只有 `进行中` 与 `待验收` 参与停滞计算。

## 双完成入口

1. **AI 自报**：`status: 已完成` + `evidence` 非空 + 正文 `## 完成方` 写 agent 标识。evidence 缺失由引擎阻断。
2. **人工确认**：frontmatter 写 `confirmed_by`（值形如 `张三 2026-01-02`），人工复核后填；字段非空才算关单。

- 关单判据：`status: 已完成` **且** `evidence` 非空 **且** `confirmed_by` 非空。
- 引擎不解析 `confirmed_by`（只取已知 key），所以它缺失不会被 scan 拦住——评审必须逐条核对这一项。
- AI 不得自己填 `confirmed_by`；填了按伪造证据处理。

## 停滞

- `进行中` / `待验收` 且 `updated` 距今超过 `stale_days`（默认 14 天）→ `BOARD-STALE`。
- 处理方式：更新进展、或改 `挂起` 并写原因与恢复条件。

## UI 类条目的证据

`board.ui_evidence_required: true` 时，`title` 或 `goal` 含 `UI` / `视觉` 的 `已完成` 条目，`evidence` 必须含「截图」并给出三联图路径：

- `expected`：设计基线/期望图
- `actual`：本次实测截图
- `diff`：pixelmatch 差异图

路径用仓库内相对路径。基线必须来自 CI 单一环境的产物，本地渲染（字体/DPR/浏览器版本不同）会产生假阳性。
