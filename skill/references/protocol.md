# 跨开发者 agent 协作协议

面向「多个开发者各自带 agent、同一个仓库并行推进」的场景。协议只约束可核对的事实：谁认领、证据在哪、下一步是什么。

## 1. 单一事实源与 git 分发

- 协议、skill、模板只在 canonical 仓库维护；其他仓库持有副本。
- 副本靠 git 分发（子树、子模块或 CI 同步均可），一致性用 `govern sync` + `SKILL-SYNC` 规则核对：canonical 与 `skills.copies` 必须字节相等。
- 禁手工双写副本：任何修改先落 canonical，再 sync；直接改副本会被下次同步覆盖。

## 2. 认领

- 认领 = 进度板条目的 `owner` 写成自己的 agent 标识，同时把工作分支对齐 `dev-<个人>`（从 `dev` 切出，改动只进个人分支）。
- 没有 markdown CAS：markdown 不支持 compare-and-swap，两人同时写 `owner` 时**独立提交先合入者赢**。后到者 rebase 后改为协作或换任务，不覆盖对方的认领提交。
- 认领后立即 push 该条目，让 owner 在远端可见；只在本地改等于没认领。
- 一个 owner 默认一个在办任务；要并行必须显式在同一仓库另开条目或写第二 owner，不允许一条任务两个 agent 各干一半。

## 3. 开工与收工

- 开工：`git fetch` 后把自己的 `dev-<个人>` 同步到 `origin/dev`（推过的个人分支用 merge，不 rebase），再把 `owner`/`updated` 推到远端。
- 收工：进展与证据写回条目 → `updated` 改当天 → push。**未 push 的进展视为没发生**。
- 跨仓改动：先在本仓条目登记跨仓依赖与对端分支，再动对端仓库。

## 4. 交接包

缺一段就不算交接：

- **进展**：已完成到哪一步，涉及的分支与提交。
- **证据**：命令 + 输出结论、截图路径、测试结果；无证据的「已完成」不成立。
- **下一步**：接手后的第一个动作 + 已知坑。

交接落在进度板条目正文（或 `doc` 指向的文件），不靠会话记录，因为下一个 agent 没有你的上下文。

## 5. 共享抽象

- token（设计变量）、共享组件、契约基类、公共脚本属于共享抽象，实行**专人制**：同一时间只有一个 owner 可改。
- 需要变更时走「提案 → owner 实施」，禁并行各改一版再合并。
- 使用方只消费，不就地改；发现缺口反馈 owner 并登记任务。

## 6. 停滞升级（黄牌）

- `进行中` / `待验收` 超过 `stale_days`（默认 14）天未更新 → `BOARD-STALE` 黄牌。
- 黄牌处理：更新进展，或改 `挂起` 并写明原因与恢复条件；无原因挂起按非法处理。
- 连续两张黄牌由人决定换人或关单；agent 不自行延长停滞。

## 7. 决策流

- agent 不做产品或架构决策，只出 brief：问题、选项、影响面、建议、需要谁拍板。
- 人拍板后把结论写回条目（或决策文档），agent 再动手。
- 影响多仓/多人的决策必须落文档，不接受只在会话里达成。

## 8. 状态词汇与 A2A 对齐

| 本协议 | A2A | 含义 |
| --- | --- | --- |
| 待启动 | submitted | 已登记未开工 |
| 进行中 | working | agent 在推进 |
| 待验收 | input-required | 等人工复核或等外部输入 |
| 已完成 | completed | AI 自报完成，带证据 |
| 挂起 | canceled | 取消/搁置，须写原因 |

- 只对齐词汇层：A2A 的 `completed` 不等于关单，本协议要求 `confirmed_by` 人工确认后才关。
- 跨 agent 调用时用 A2A 词汇通信，落板时用本协议枚举（`board.statuses`）。

## 9. 跨仓原子性（诚实标注）

跨仓原子提交目前没有成熟方案：git 无法让两个仓库的改动同时生效或同时回滚。因此：

- **契约先行**：接口先进契约仓库（或本仓 `docs/接口/`），合并后实现方再改。
- **兼容窗口**：新旧字段/接口并存一个发布周期，字段只增不改不删。
- **ticket 串联**：每个仓库一个 ticket，互相引用对方提交；回滚按 ticket 反序执行。
- 已知代价：窗口期内两端版本组合不是全排列可用，用契约测试（breaking + regen 比对）兜住。
